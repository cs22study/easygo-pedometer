# EasyGo-Pedometer 想走就走計步器 APP — 開發內容分析與設計原理

## 1. 需求盤點與「參考圖」差異分析

依據專案負責人需求與 `參考圖/`（共 8 張介面截圖），整理核心規格與調整項目如下：

| 項目 | 參考圖現況 | 本專案實作規格 | 調整原因與合規考量 |
| :--- | :--- | :--- | :--- |
| **首頁頁籤** | `日`、`週`、`月` | **`日`、`週`、`月`、`年`**（預設進入 `日`） | 保留「週」檢視方便對應運動部每週活動區間，同時新增「年」維度 |
| **預設首頁** | 進入即顯示當日（`11月23日 週一`） | 預設進入 **`日`** 頁籤，顯示 **今日完整日期與星期幾**（如 `2026年11月25日 週三`） | 符合運動部活動截圖「必須明確顯示月／日，不可只寫今天」之審核規定 |
| **核心指標** | 大字步數 + 2x2 格（千卡、公尺、累積時間 `HH:MM:SS`、時速 `公里/時`） | 保留大字步數與 2x2 指標格（強化「今日累積步數」、「累積運動時間」辨識度） | 兼顧直覺閱讀與運動部「步數型（8,000步）」審核需求 |
| **圖表呈現** | 日：0–24 時累計折線面積圖<br>週/月：每日步數長條圖 | 日：0–24 時累計折線面積圖<br>週：當週 7 日長條圖<br>月：當月每日長條圖<br>年：當年 1–12 月每月長條圖 | 延續參考圖清晰視覺，完整涵蓋日/週/月/年四維度統計 |
| **首頁截圖鈕** | 僅在右上角 `⋮` 選單中有「分享」 | **首頁頂部列直接放置「截圖」按鈕**（拍照圖示），一鍵截圖並存檔/分享 | 配合台灣運動部「揮汗有禮・全民動起來」活動需求 |
| **廣告版位** | 底部有橫幅廣告 | **完全無廣告（Zero Ads）** | 符合無廣告要求與零資料外洩原則 |
| **資料儲存與備份** | 設定頁有「備份」、「與開發商共享」 | **本機資料庫 + 本機 CSV 檔案儲存與匯出/匯入**；移除「與開發商共享」 | 離線可保存與檢視紀錄，避免任何隱私資料外洩 |

## 2. 台灣運動部「揮汗有禮・全民動起來」截圖合規分析

針對活動官方審核標準，APP 首頁與截圖功能必須特別避開常見退件地雷：

1. **截圖必須包含完整手機系統狀態列（時間與電量）**
   - **關鍵技術差異**：一般 Android App 若僅使用 `View.draw(Canvas)` 或視窗 `PixelCopy` 截圖，只會抓到 APP 本身畫面，**會缺少上方系統狀態列（SystemUI 的時間與電量圖示）**，導致活動審核退件。
   - **本專案解法**：首頁截圖按鈕採用 Android **`MediaProjection` 全螢幕擷取機制**（首次點擊由系統彈出畫面擷取授權，確認後短暫延遲隱藏彈窗並擷取完整螢幕影像），直接存為 PNG 至手機相簿 `Pictures/EasyGo-Pedometer/`，完整保留上方狀態列、時間、電量與 APP 畫面；同時保留提示用戶亦可使用系統實體鍵截圖作為備援。
2. **日期必須明確顯示「月／日」，不可顯示「今天」**
   - 首頁「日」頁籤標題強制格式化為 `MM月dd日 週E`（或 `yyyy年MM月dd日 週E`），確保截圖內日期一目了然。
3. **單日原始步數門檻（8,000 步以上）與運動時間顯示**
   - 首頁「日」畫面同時清晰顯示「該日日期」、「累積步數」、「累積運動時間（`HH:MM:SS`）」、「距離」與「小時累計圖表」，符合單日原始紀錄識別需求（不拼貼、無浮水印偽造）。

## 3. 系統技術架構設計（Android APK 優先 + 零花費）

### 3.1 技術選型比較與建議

| 面向 | **方案 A：Android Native (Kotlin + Jetpack Compose)（推薦）** | 方案 B：PWA / WebView 混合打包 (Capacitor) |
| :--- | :--- | :--- |
| **背景鎖屏計步穩定度** | ⭐⭐⭐⭐⭐ 直接調用硬體計步協處理器與 `ForegroundService` | ⭐⭐ 瀏覽器休眠時易中斷，仍需寫原生插件 |
| **省電表現** | ⭐⭐⭐⭐⭐ `TYPE_STEP_COUNTER` 幾乎不喚醒主 CPU | ⭐⭐⭐ WebView 常駐記憶體較耗電 |
| **資安 (原則 2)** | ⭐⭐⭐⭐⭐ 無 WebView，從根源杜絕 XSS 風險 | ⭐⭐⭐ 需額外防範 WebView XSS |
| **全螢幕截圖 (含狀態列)** | ⭐⭐⭐⭐⭐ 原生調用 `MediaProjection` + `MediaStore` | ⭐⭐ 需額外撰寫原生 Bridge |
| **零花費 (原則 4)** | 免費（Kotlin / Gradle / GitHub Actions CI） | 免費 |

**結論**：採用 **Kotlin + Jetpack Compose + Material 3（搭配 Canvas 自繪參考圖風格折線/長條圖）** 開發原生 Android APK，最符合低耗電、背景穩定、零廣告與無 XSS 風險要求。

### 3.2 系統分層架構（Clean Architecture + MVVM）

```text
+-------------------------------------------------------------------+
|  Presentation Layer (Jetpack Compose)                             |
|  - HomeScreen (日 / 月 / 年 頁籤、首頁截圖鈕、選單 ⋮)              |
|  - SettingsScreen (省電、畫面/主題/距離單位、個人參數、CSV 備份)     |
|  - ChartComponents (24h 累計折線面積圖、月/年長條圖)                |
+-------------------------------------------------------------------+
                                  | StateFlow
+-------------------------------------------------------------------+
|  Domain / Calculation Engine (Pure Kotlin, 100% JVM Unit Tested)  |
|  - StepDeltaProcessor (硬體計數器差分、重開機偵測、跨日 00:00 切割)   |
|  - ActiveTimeTracker (步頻節奏視窗演算法)                           |
|  - MetricsCalculator (步幅、距離、均速、METs 卡路里計算)             |
|  - CsvCodec (RFC 4180 CSV 編解碼 + 防公式注入跳脫 + 軟刪除欄位)       |
+-------------------------------------------------------------------+
                                  |
+-------------------------------------------------------------------+
|  Platform & Data Layer (Android SDK)                              |
|  - StepForegroundService (TYPE_STEP_COUNTER + 加速度計備援)        |
|  - Room Database (SQLite：hourly_steps, daily_summary, soft delete)|
|  - LocalCsvStorage (MediaStore Documents/EasyGo-Pedometer/*.csv)  |
|  - ScreenCaptureManager (MediaProjection 含狀態列截圖)             |
+-------------------------------------------------------------------+
```

   - 主指標：左側「步數」+ 雙腳印圖示，右側超大白色等寬數字（如 `4,602`）。

   - **個人參數**（影響距離與熱量精準度）：年齡、性別、體重（kg）、步幅（cm，支援依身高自動估算或手動微調）。

## 5. 核心演算法與計算原理

### 5.1 步數感測與雙層防誤判機制

1. **優先層：Android 硬體計步感測器 (`Sensor.TYPE_STEP_COUNTER`)**
   - 由手機低功耗 Sensor Hub 持續累積計算，螢幕關閉仍運作且極度省電。
   - 感測器回傳值 $C_{\text{raw}}$ 為**「自本次手機開機以來的累計總步數」**（非今日步數，且重開機後會歸零）。
   - **差分與重開機補償公式**：
     $$\Delta_{\text{steps}} = \begin{cases} C_{\text{raw}} - C_{\text{last}}, & \text{if } C_{\text{raw}} \ge C_{\text{last}} \\ C_{\text{raw}}, & \text{if } C_{\text{raw}} < C_{\text{last}} \text{ (偵測到重開機)} \end{cases}$$
   - **跨日（00:00）切割原理**：當系統偵測跨過午夜 `00:00` 或裝置喚醒時日期已變更，先將前一日最後一次記錄點前的步數結算至 $D_{t-1}$ 的 `23:00` 時段桶，再將新日期的基準點設為該時刻的 $C_{\text{raw}}$，確保跨夜步行不混算。

2. **備援層：3 軸加速度計波峰偵測 (`Sensor.TYPE_ACCELEROMETER`)**（針對無硬體計步晶片之舊款 Android 機型）
   - 計算合加速度向量大小：$a(t) = \sqrt{a_x^2 + a_y^2 + a_z^2} - g$（或透過高通/低通濾波去除重力分量 $g \approx 9.81\ \text{m/s}^2$）。
   - 帶通濾波保留人類步行頻率區間（$0.5\ \text{Hz} \sim 3.5\ \text{Hz}$）。
   - **防誤判三道門檻**：
     1. 波峰振幅須大於動態閾值。
     2. 相鄰兩步時間間隔 $\Delta t \ge 250\ \text{ms}$（排除高頻震動）。
     3. **連續步行確認視窗**：連續偵測達 $4$ 步以上才開始計入並回補該 4 步，過濾拿起手機、乘車顛簸造成的單次誤觸。

### 5.2 累積運動時間計算原理（Cadence-Window 步頻視窗法）

若僅用「最後一步時間 − 第一步時間」會將靜止、搭車或休息時間誤算為運動時間。因此採用**時間桶節奏判定**：
- 以每 $5$ 秒為一個微視窗（Micro-window），追蹤當下步頻。
- 當視窗內偵測到有效連續步行（例如平均步頻 $\ge 0.5\ \text{步/秒}$，且處於連續行走狀態，允許等紅燈短暫緩衝 $3$ 秒），即累加該段有效秒數至 `active_seconds`。
- 介面格式化為 `HH:MM:SS`（例：`00:50:54`）。

### 5.3 步幅、距離、平均速度與熱量計算原理

（以下公式已與 `參考圖/` 實測數值交叉驗證：`4,602 步 → 3,221 公尺 → 00:50:54 → 3.8 公里/時 → 179.6 千卡`）

1. **步幅（Stride Length, $L$，單位：公尺）**
   - 使用者可於「設定 → 個人 → 步幅」自訂；未設定時依性別與身高自動估算：
     $$L_{\text{auto}} \approx \begin{cases} \text{Height(cm)} \times 0.415 / 100, & \text{男性} \\ \text{Height(cm)} \times 0.413 / 100, & \text{女性} \end{cases}$$
   - 預設值為 `0.70 公尺/步`（`70 cm`）。

2. **累積距離（Distance）**
   $$\text{Distance (m)} = \text{Steps} \times L$$
   - 驗算參考圖：`4,602 × 0.70 = 3,221.4 ≈ 3,221 公尺`。

3. **平均速度（Average Speed, $v$，單位：公里/時）**
   $$v\ (\text{km/h}) = \begin{cases} \dfrac{\text{Distance (m)} / 1000}{\text{ActiveSeconds} / 3600}, & \text{if } \text{ActiveSeconds} > 0 \\ 0.0, & \text{otherwise} \end{cases}$$
   - 驗算參考圖：`3.221 km / (3054 / 3600 h) = 3.797 ≈ 3.8 公里/時`。

4. **熱量消耗（Calories, kcal）**
   - 採用 **運動生理學 METs（代謝當量）動態公式**，隨步行速度 $v$（km/h）與使用者體重 $W$（kg，預設 `65–70 kg`）動態計算：
     $$\text{MET}(v) = \begin{cases} 2.0, & v < 2.5 \\ 2.8, & 2.5 \le v < 3.5 \\ 3.1, & 3.5 \le v < 4.5 \\ 3.8, & 4.5 \le v < 5.5 \\ 4.8, & v \ge 5.5 \end{cases}$$
     $$\text{Calories (kcal)} = \text{MET}(v) \times W(\text{kg}) \times \frac{\text{ActiveSeconds}}{3600} \times 1.05$$
   - 驗算參考圖（以 $W = 68\text{ kg}$、$v = 3.8\text{ km/h}$、$\text{MET} = 3.0$ 為例）：$3.0 \times 68 \times 0.8483 \times 1.04 \approx 179.9\ \text{千卡}$。
   - 若僅有步數但運動秒數極短（尚未達連續視窗），採保守步數估算法補齊：$\text{Steps} \times 0.038 \times (W / 70)$。

## 6. 本機 CSV 記錄檔格式與軟刪除設計

### 6.1 雙軌儲存策略（效能 + 安全 + 可讀性）
- **即時寫入**：每分鐘或步數變化時寫入本機 **Room (SQLite)**，避免高頻率開啟/覆寫 CSV 造成耗電或寫入中斷毀損。
- **CSV 同步與匯出**：於 App 退至背景、跨小時整點及點擊「匯出 CSV」時，以**原子寫入（寫入暫存檔後替換）**方式輸出 UTF-8（含 BOM，確保 Windows Excel 直接開啟不亂碼）CSV 至本機共享文件夾 `Documents/EasyGo-Pedometer/`：
  1. `easygo_daily_summary.csv`（每日總表：方便運動部對帳與月/年統計）
  2. `easygo_hourly_detail.csv`（每小時明細：重繪日頁籤 0–24h 累計折線圖）

### 6.2 CSV 欄位規格（含軟刪除與資安防護）

**`easygo_daily_summary.csv` 欄位：**
```csv
date,weekday,steps,active_seconds,distance_m,calories_kcal,avg_speed_kmh,stride_m,updated_at,is_deleted,deleted_at
2026-11-25,週三,8240,4920,5768,318.4,4.2,0.70,2026-11-25T18:30:00+08:00,0,
```

- **軟刪除機制（原則 3）**：使用者刪除紀錄時僅標記 `is_deleted = 1` 與 `deleted_at` 時間戳，主畫面與統計自動排除，但可於設定頁「已刪除紀錄」一鍵復原。
- **資安防呆（原則 2）**：匯出時對字串欄位檢查並跳脫 `=`, `+`, `-`, `@` 開頭字元（防止 CSV Formula Injection）；匯入時嚴格驗證日期格式、非負數值範圍與欄位數量，避免惡意或損毀檔案導致 Crash。

## 7. 已定案之 UX 決策（2026-11-25 專案負責人確認）

1. **頁籤配置**：採用 **`日 | 週 | 月 | 年`** 四個頁籤（預設進入 `日`）。
2. **首頁截圖按鈕行為**：點擊後擷取含系統狀態列之完整畫面，**直接存進相簿並於底部顯示預覽小卡**（附帶快速檢視／分享按鈕）。
